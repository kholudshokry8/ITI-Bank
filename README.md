# CreditCopilot Lite

A grounded RAG assistant for personal-loan underwriting at **Delta Commercial Bank** (a fictional bank).
It answers policy questions with clause-level citations, refuses when the documents do not cover a question, and prepares a credit recommendation that a human credit officer approves or rejects.

> Training exercise on **synthetic data**. Nothing here is real lending policy or financial advice.

Four rules the code enforces: answers are **grounded** (or refused), **numbers are never generated by the LLM**, **protected attributes are removed in code** (and a test proves it), and **a human approves** before any offer is issued.

## Quick start

Requires Node 22 or 24. `better-sqlite3` is pinned to 12.11.1 because it ships prebuilt binaries for both; version 11.x has none for Node 24 on Windows and tries to compile from source (needs Python and C++ build tools).

```bash
npm ci
cp .env.example .env        # then set JWT_SECRET (e.g. openssl rand -hex 32)
npm run seed                # demo users + the five application packs (untrusted store)
npm run ingest              # policy documents -> chunks -> embeddings -> index
npm start                   # http://localhost:3000   (API docs: /docs)
```

Docker: `cp .env.example .env`, set `JWT_SECRET`, then `docker compose up` (the container seeds and ingests on start).
_The Docker setup was written but not run in the environment this was built in; run it once before relying on it._

Default provider is `mock` (offline, no API key). See "LLM providers" for real models.

## Demo accounts (synthetic)

| Role                  | Username         | Password        | Can do                                       |
| --------------------- | ---------------- | --------------- | -------------------------------------------- |
| Loan Officer          | `loan.officer`   | `Demo-Loan-1`   | ask, assess applications (cannot approve)    |
| Credit Officer        | `credit.officer` | `Demo-Credit-1` | also approve/reject up to EGP 250,000, issue |
| Senior Credit Officer | `senior.officer` | `Demo-Senior-1` | approve up to EGP 500,000, referred files    |

The brief asks for two roles; a third is needed because PM-2 gives a Senior Credit Officer authority above 250,000 and APP-001 (EGP 300,000) cannot be approved by a Credit Officer. Limits live in `config/policy-editions.json`.

## 5-Minute Demo Path

1. Start the app, open `http://localhost:3000`, log in as `loan.officer`.
2. **Ingest** tab (log in as `credit.officer` for this one): run ingestion; 7 documents, 82 chunks. Run it twice: the count does not change.
3. **Ask**: "What is the maximum debt burden ratio?" returns the 2025 clause `CP-2025:CP-4.1` with file, page and score.
4. **Ask** (refusal): "What is the bank's policy on crypto-backed loans?" returns the "documents do not contain enough information" answer, no citations.
5. **Ask** (editions): "What was the maximum debt burden ratio in the 2024 policy?" returns 50% from `CP-2024`; the previous question returned 45%.
6. **Assess** `APP-002`: edition 2025, instalment 10,068.79, DBR 46.90% fails 45%, reduced offer 330,000. Every rule row shows a citation.
7. **Assess** `APP-004`: the salary certificate contains a hidden instruction; income stays 18,000, the attempt is logged, result is **refer** (PM-7).
8. As `credit.officer`, open the APP-001 assessment (prepared by the loan officer) and **Approve**: the server answers `authority_limit_exceeded` (300,000 > 250,000). Log in as `senior.officer`, approve, then **Issue**.

## LLM providers

- `mock` (default): an offline stand-in. It extracts fields with regular expressions, fills templates, and uses **lexical** hashed vectors. It is **not** a language model and its vectors are **not semantic**. It exists so everything runs and tests pass without a key.
- `gemini`: `LLM_PROVIDER=gemini GEMINI_API_KEY=... npm run ingest` (re-ingest after switching: embeddings from different models are not comparable and are stored per model). **This adapter has not been run against the live service in this repository's tests.**

## What data is sent to the LLM provider

Only with a real provider (`gemini`). Nothing leaves the machine with `mock`.

- **Extraction:** the salary-certificate and bureau-summary text of one application, after redaction: names, national IDs, phone numbers, gendered titles and pronouns, and protected-attribute words are replaced by placeholders. The application form itself is **not** sent.
- **Credit memo:** the application id, policy edition, recommendation, and one line per rule (rule name, clause, result, and detail such as "Net income EGP 18,000").
- **Q&A:** the question text and up to three policy chunks.
- **Embeddings:** policy chunk text at ingestion; the question or rule query at search time.

## Layout

```
src/domain/   pure rules: calculations, rules, policy editions, redaction, extraction checks, approval (no LLM/DB/network)
src/app/      pipeline, Q&A, ingestion, chunking; depends only on interfaces in ports.ts
src/infra/    LLM adapters, SQLite, vector search, web server
config/       policy edition values, authority limits, document metadata
prompts/      all prompts (files, not strings in code)
migrations/   SQL schema migrations
data/         the provided synthetic document pack
docs/         DESIGN.md, EVALUATION.md, AI-USAGE-LOG.md
```
